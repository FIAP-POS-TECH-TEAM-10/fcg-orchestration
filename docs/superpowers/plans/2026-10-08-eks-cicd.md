# Pipeline CI/CD dos serviços (Fase 4 — Parte 3a) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um `ci-cd.yml` em users, catalog e payments que faz build → teste → Trivy → push no ECR → rolling update no EKS (pulando o deploy quando o cluster está desligado), mais a policy permanente `eks:DescribeCluster` da role do GitHub.

**Architecture:** Workflow GitHub Actions autossuficiente em cada repo de serviço (3 jobs: `build-test`, `image`, `deploy`), autenticando na AWS via OIDC com a role existente `GitHubActions-ECS-Deploy-Role`. Um Terraform permanente em `fcg-orchestration/infra/github-ci/` passa a ser o dono da permissão `eks:DescribeCluster` (antes criada e destruída junto com o cluster).

**Tech Stack:** GitHub Actions (`actions/checkout@v4`, `actions/setup-dotnet@v4`, `aws-actions/configure-aws-credentials@v4`, `aws-actions/amazon-ecr-login@v2`, `github/codeql-action/upload-sarif@v3`), Trivy via imagem `aquasec/trivy`, Docker BuildKit, .NET 10, kubectl, Terraform ≥ 1.5.

**Spec:** `fcg-orchestration/docs/superpowers/specs/2026-10-08-eks-cicd-design.md`

```hcl
# Permissões PERMANENTES da role do GitHub Actions ligadas ao EKS.
# NUNCA destruir — os scripts liga/desliga (scripts/eks-*.sh) não tocam neste state.
# Motivo: o pipeline dos serviços chama `aws eks describe-cluster` para saber se o cluster
# está ligado. Se esta permissão morresse junto com o cluster (como era em infra/eks), com o
# cluster desligado a resposta seria AccessDenied em vez de ResourceNotFoundException e o
# pipeline não conseguiria distinguir "desligado" de "erro".
terraform {
  required_version = ">= 1.5.0"

  required_providers {
    aws = {
      source  = "hashicorp/aws"
      version = "~> 5.95"
    }
  }

  backend "s3" {
    bucket         = "fiap-tech-challenge-tfstate-123456-915153720516-sa-east-1-an"
    key            = "github-ci/terraform.tfstate"
    region         = "sa-east-1"
    dynamodb_table = "fiap-tech-challenge-tflocks"
    encrypt        = true
  }
}

provider "aws" {
  region = "sa-east-1"
}

locals {
  github_role_name = "GitHubActions-ECS-Deploy-Role"
  eks_cluster_arn  = "arn:aws:eks:sa-east-1:915153720516:cluster/fcg-eks"
}

# describe-cluster: checar se o cluster existe + `aws eks update-kubeconfig`.
# O acesso DENTRO do cluster (edit no namespace fcgames) continua vindo do access entry
# criado pelo Terraform do cluster (infra/eks) a cada eks-up.
resource "aws_iam_role_policy" "github_eks_describe" {
  name = "fcg-github-eks-describe"
  role = local.github_role_name

  policy = jsonencode({
    Version = "2012-10-17"
    Statement = [{
      Effect   = "Allow"
      Action   = ["eks:DescribeCluster"]
      Resource = local.eks_cluster_arn
    }]
  })
}
```

- [ ] **Step 1: Criar `ci-cd.yml`**

```yaml
# Pipeline do UsersAPI (Fase 4): build → testes → imagem + Trivy → ECR → rolling update no EKS.
#   pull_request → build, testes, imagem e Trivy (não publica nada)
#   push na main / manual → + push no ECR (:<sha> e :latest) + deploy no EKS
# Cluster fcg-eks desligado (liga/desliga por sessão) → deploy pulado com aviso, run verde;
# a imagem :latest entra no próximo ./scripts/eks-up.sh (fcg-orchestration).
name: CI/CD

on:
  pull_request:
    branches: [main]
  push:
    branches: [main]
  workflow_dispatch:

# Na main os deploys entram em fila (nunca cancela um rollout no meio); em PR, push novo cancela o anterior.
concurrency:
  group: ci-cd-${{ github.ref }}
  cancel-in-progress: ${{ github.event_name == 'pull_request' }}

permissions:
  id-token: write        # OIDC com a AWS (sem access key)
  contents: read
  security-events: write # SARIF do Trivy na aba Security

env:
  AWS_REGION: sa-east-1
  ROLE_TO_ASSUME: arn:aws:iam::915153720516:role/GitHubActions-ECS-Deploy-Role
  REGISTRY: 915153720516.dkr.ecr.sa-east-1.amazonaws.com
  ECR_REPOSITORY: fcg-users-service
  EKS_CLUSTER: fcg-eks
  K8S_NAMESPACE: fcgames
  DEPLOYMENT: users-api
  SOLUTION: app/src/Fiap.FCGames.Users.slnx

jobs:
  build-test:
    name: Build & testes
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      - uses: actions/setup-dotnet@v4
        with:
          dotnet-version: 10.0.x

      - name: Restore (pacote privado FCGames.IntegrationEvents)
        run: dotnet restore "$SOLUTION"
        env:
          NUGET_AUTH_TOKEN: ${{ secrets.PAT_PACKAGES }}

      - name: Build
        run: dotnet build "$SOLUTION" --no-restore -c Release

      - name: Testes unitários
        run: |
          if find . -name '*Tests.csproj' -not -path '*/bin/*' -not -path '*/obj/*' | grep -q .; then
            dotnet test "$SOLUTION" --no-build -c Release
          else
            echo "::warning::Nenhum projeto de teste (*Tests.csproj) encontrado — pendência da Fase 4: testes unitários."
            echo "⚠️ Nenhum projeto de teste encontrado — pendência: testes unitários." >> "$GITHUB_STEP_SUMMARY"
          fi

  image:
    name: Imagem + Trivy + ECR
    needs: build-test
    runs-on: ubuntu-latest
    outputs:
      tag: ${{ steps.meta.outputs.tag }}
    steps:
      - uses: actions/checkout@v4

      - name: Tag da imagem
        id: meta
        run: echo "tag=${GITHUB_SHA::7}" >> "$GITHUB_OUTPUT"

      - name: Build da imagem
        env:
          NUGET_AUTH_TOKEN: ${{ secrets.PAT_PACKAGES }}
          TAG: ${{ steps.meta.outputs.tag }}
        run: |
          docker build --platform linux/amd64 \
            --secret id=GITHUB_TOKEN,env=NUGET_AUTH_TOKEN \
            -t "$REGISTRY/$ECR_REPOSITORY:$TAG" \
            -t "$REGISTRY/$ECR_REPOSITORY:latest" .

      - name: Trivy (CRITICAL/HIGH — só reporta, não bloqueia)
        env:
          TAG: ${{ steps.meta.outputs.tag }}
        run: |
          mkdir -p trivy
          img="$REGISTRY/$ECR_REPOSITORY:$TAG"
          trivy() {
            docker run --rm -v /var/run/docker.sock:/var/run/docker.sock \
              -v trivy-cache:/root/.cache -v "$PWD/trivy:/out" \
              aquasec/trivy:latest image --quiet --severity CRITICAL,HIGH --exit-code 0 "$@"
          }
          trivy --format sarif --output /out/api.sarif "$img"
          trivy --format table "$img" > trivy/api.txt
          {
            echo "### 🔎 Trivy — \`$img\` (CRITICAL/HIGH)"
            echo '```'
            head -c 60000 trivy/api.txt
            echo '```'
          } >> "$GITHUB_STEP_SUMMARY"

      - name: Trivy → aba Security
        uses: github/codeql-action/upload-sarif@v3
        with:
          sarif_file: trivy/api.sarif
          category: trivy-api

      - name: Login na AWS (OIDC)
        if: github.event_name != 'pull_request'
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ env.ROLE_TO_ASSUME }}
          aws-region: ${{ env.AWS_REGION }}

      - name: Login no ECR
        if: github.event_name != 'pull_request'
        uses: aws-actions/amazon-ecr-login@v2

      - name: Push para o ECR
        if: github.event_name != 'pull_request'
        env:
          TAG: ${{ steps.meta.outputs.tag }}
        run: |
          docker push "$REGISTRY/$ECR_REPOSITORY:$TAG"
          docker push "$REGISTRY/$ECR_REPOSITORY:latest"
          echo "📦 Publicado: \`$REGISTRY/$ECR_REPOSITORY:$TAG\` (+ \`:latest\`)" >> "$GITHUB_STEP_SUMMARY"

  deploy:
    name: Deploy no EKS (rolling update)
    needs: image
    if: github.event_name != 'pull_request'
    runs-on: ubuntu-latest
    steps:
      - name: Login na AWS (OIDC)
        uses: aws-actions/configure-aws-credentials@v4
        with:
          role-to-assume: ${{ env.ROLE_TO_ASSUME }}
          aws-region: ${{ env.AWS_REGION }}

      - name: Cluster ligado?
        id: cluster
        run: |
          if status=$(aws eks describe-cluster --name "$EKS_CLUSTER" --query cluster.status --output text 2>err.txt); then
            if [ "$status" = "ACTIVE" ]; then
              echo "up=true" >> "$GITHUB_OUTPUT"
            else
              echo "up=false" >> "$GITHUB_OUTPUT"
              echo "### ⏭️ Deploy pulado: cluster \`$EKS_CLUSTER\` está $status" >> "$GITHUB_STEP_SUMMARY"
            fi
          elif grep -q ResourceNotFoundException err.txt; then
            echo "up=false" >> "$GITHUB_OUTPUT"
            {
              echo "### ⏭️ Deploy pulado: cluster \`$EKS_CLUSTER\` desligado"
              echo "A imagem \`:${{ needs.image.outputs.tag }}\` (e \`:latest\`) já está no ECR e entra no próximo \`./scripts/eks-up.sh\`."
            } >> "$GITHUB_STEP_SUMMARY"
          else
            cat err.txt
            exit 1
          fi

      - name: Rolling update
        if: steps.cluster.outputs.up == 'true'
        env:
          TAG: ${{ needs.image.outputs.tag }}
        run: |
          aws eks update-kubeconfig --name "$EKS_CLUSTER" --region "$AWS_REGION"
          kubectl set image "deploy/$DEPLOYMENT" -n "$K8S_NAMESPACE" \
            api="$REGISTRY/$ECR_REPOSITORY:$TAG"
          kubectl rollout status "deploy/$DEPLOYMENT" -n "$K8S_NAMESPACE" --timeout=600s
          {
            echo "### ✅ Deploy concluído (rolling update, sem downtime)"
            echo "Imagem: \`$REGISTRY/$ECR_REPOSITORY:$TAG\`"
            echo '```'
            kubectl get pods -n "$K8S_NAMESPACE" -l app="$DEPLOYMENT" -o wide
            echo '```'
          } >> "$GITHUB_STEP_SUMMARY"
```
